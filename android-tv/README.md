# aviavp — свой Android-клиент

Форк [v2rayNG](https://github.com/2dust/v2rayNG) (GPL-3.0) с интерфейсом в духе
V2Box и полностью вынесенным брендом. Ядро — xray, то же самое, под которое
настроена наша панель.

## Несколько приложений из одного кода

У каждого приложения свой файл `brands/<id>.properties` и свои картинки
в `brands/<id>/`. Сейчас их два:

| id | имя | пакет | бэкенд |
|---|---|---|---|
| `aviavp` | aviavp | `online.tforge.aviavp` | `/aviavp` |
| `proxyvv` | PV | `online.tforge.proxyvv` | `/proxyvv` |

```bash
./build.sh                 # бренд по умолчанию (aviavp)
BRAND=proxyvv ./build.sh   # другое приложение
```

В файле бренда — имя, идентификатор пакета, версия, четыре цвета, ссылки,
схема диплинка и путь к иконке. Ни имени, ни цвета, ни адреса в коде нет:
`build.gradle.kts` читает нужный файл и кладёт значения в `BuildConfig`,
а экраны берут их из единственного объекта `ui/compose/Brand.kt`.

Иконки берутся двумя способами. Если в `brand.icon.android` указан каталог
с готовым набором по плотностям — он копируется как есть: в таком наборе
передний план и фон уже разведены как надо для адаптивной иконки.
Иначе всё собирается из одной картинки `brand.icon.source`: скрипт находит
в ней знак, отбрасывает подпись под ним и делает все плотности сам.

⚠️ Ресурсы в проекте общие, поэтому в рабочем дереве лежат картинки
последнего собранного бренда. Это нормально: `build.sh` всегда прогоняет
`rebrand.sh` перед сборкой.

⚠️ `brand.applicationId` — это удостоверение приложения в системе. Поменяешь
его у уже выпущенного приложения — обновление поверх не встанет, только
переустановка с потерей настроек.

## Сборка

Идёт на сборочной машине, где развёрнуто окружение:

| что | где |
|---|---|
| Android SDK 37 + NDK | `/opt/android/sdk` |
| исходники | `/opt/build/aviavp` |
| ключ подписи | `/opt/build/keystore/aviavp.jks`, пароль рядом в `password` |

```bash
rsync -az --exclude .git --exclude build/ --exclude .gradle/ \
      ./ claude@СБОРОЧНАЯ-МАШИНА:/opt/build/aviavp/
ssh claude@СБОРОЧНАЯ-МАШИНА 'cd /opt/build/aviavp && ./build.sh'
```

По умолчанию собирается arm64 — это 95% телефонов. `ABI=universal ./build.sh`
даёт один APK под все архитектуры, он примерно вдвое тяжелее.

🔑 **Ключ подписи нельзя терять.** Без него невозможно выпустить обновление для
уже установленного приложения. Он намеренно лежит вне репозитория.

## Чем отличается от исходного v2rayNG

- Нижние вкладки «Главная / Серверы / Настройки» вместо бокового меню.
- Главный экран: один круг-кнопка — выключено показывает знак питания,
  включено показывает время соединения; под ним выбранный сервер.
- Тёмная тема по умолчанию. Палитра снята пипеткой со скриншотов V2Box:
  чёрный фон, серые карточки, светло-серая нижняя панель и бирюзовый акцент
  только на активном. Подстройка под обои системы выключена, иначе
  приложение перекрашивалось бы в чужие цвета.
- Меню «+» двухуровневое, как в V2Box: сверху частые действия и «добавить
  подписку», список протоколов убран на второй уровень.
- Один вариант сборки вместо F-Droid/Play Store.
- `Utils.isXray()` больше не угадывает ядро по имени пакета — переименование
  приложения это ломало.
- Удалить можно любой профиль, кроме того, на котором прямо сейчас поднято
  соединение. В исходном проекте удаление выбранного профиля запрещалось
  всегда, а выбранным он остаётся и после отключения — то есть удалить его
  было нельзя никогда, и сообщение причину не называло.
- Схема диплинка своя (`aviavp://install-sub?url=…`), а не `v2rayng://`:
  иначе при установленном рядом v2rayNG Android спрашивал бы, чем открывать.
  Бот отдаёт такую ссылку кнопкой «aviavp» в списке приложений.
